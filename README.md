# Autumn in China

A static travel guide with a Bahasa Indonesia interface for 8–21 November 2026. Built with Vite, TypeScript, semantic HTML, and plain CSS.

Public website: [china.muhammadyana.me](https://china.muhammadyana.me). Browse the [destination directory](https://china.muhammadyana.me/places/) or open a guide such as [/places/jiuzhaigou/](https://china.muhammadyana.me/places/jiuzhaigou/).

## Run locally

```sh
git clone https://github.com/muhammadyana/china-itinerary.git
cd china-itinerary
npm install
npm run dev
```

## Build and preview production

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
```

Open <http://127.0.0.1:4173/>. To jump directly to 20 November, open <http://127.0.0.1:4173/#2026-11-20>.

Upload the contents of `dist/` to a static host. Assets use root-relative paths; deploy at the domain root. Nginx serves each destination directory through its generated `index.html`; the site requires no backend, API keys, third-party font loading, or runtime image service. The PDF is downloaded only when its link is opened.

## Update the itinerary

`src/itinerary.ts` is the single source of truth for dates, places with stable IDs, captions, photos, credits, transfers, practical notes, and overnight stays. The date picker, route overview, ten regional highlights, hero, and daily view share this data. `src/render.ts` renders the same HTML during the build and when a date is selected. `src/main.ts` handles DOM interactions, dialogs, the clipboard, and URL history.

Homepage cards and hero slides use shared image resolution and dedicated render functions, so a new highlight is added once to the data registry. The date picker reuses the same date-choice renderer as the sidebar; `src/date-picker.css` owns its scoped layout. Phones show one readable column in a scrollable list beneath a fixed dialog header; larger screens use two columns. Selection, Escape, focus restoration, and date history retain the existing behavior.

Homepage and destination photo dialogs share `renderPhotoDialog` and `src/photo-viewer.ts`. Previous/next buttons sit in dedicated side gutters at the picture's vertical midpoint, with 44px touch targets and no overlap on the image. The counter and close button remain separate above it. Paging replaces only the image and caption, preserving button focus, keyboard navigation, and the complete photo. Single itinerary photos hide the paging controls and use the full available width.

All headers share `src/site-navigation.ts`: Home, the day-by-day itinerary anchor, a Places dropdown, the gallery, and the route overview. Home is a compact 44px logo link named Beranda (`src/logo.ts`, shared with the header wordmark); the other labels are Itinerary, Tempat, Galeri, and Rute. The wider glass menu stays centered at the top while scrolling; the wordmark remains in normal document flow on wide layouts and is hidden at 1000px and below, where the menu is the only header. Shared anchor clearance prevents headings from being hidden beneath the menu. The dropdown lists unique sightseeing stops from the actual itinerary, grouped by province; airports, stations, and hotel bases are excluded. Native details keeps the links available without JavaScript; Escape and outside-click dismissal enhance it. The itinerary link preserves the selected day when used on the homepage. The route overview is also available beside the date picker. PDF downloads stay in the footer and guide/day links, outside the top menu. The Places menu also links to `/places/prepare/` (`src/prepare.ts`): what is already done, a booking checklist grouped by urgency with release times, a cost estimate summed from the checklist and the stay picks, and internet, emergency, insurance and altitude notes. `/places/costs/` (`src/costs.ts`, `src/costs-render.ts`) breaks that same estimate down per day and per line; both pages sum the same rounded lines, so their totals match. The Places menu and the route overview also link to `/places/map/`, a static route map (`src/route-map.ts`) whose province and river outlines are generated by `node ops/prepare-route-map.mjs <Natural Earth directory>` into `src/route-map-geo.ts`. `/places/calm/` compares a calmer one-way alternative: its days, bookings and map points are in `src/calm-route.ts` (8 and 18–21 November are read from the main plan), and `src/calm-render.ts` renders the page with the same `routeMapLayout` as the route map.

The destination directory uses the shared `renderDestinationCard` renderer, wide responsive photographs, and accessible stop-link chips. `src/chengdu-evening.ts` supplies the first-night mall cards to the day, Chengdu guide, and generated PDF: Chengdu SKP, the required Vitality Tower stop, links to its guide, and four other malls stay as fallbacks. Every stop card and place page links to Amap through `src/amap.ts` (one keyword, adcode and optional verified point per place); `vite.config.ts` fails the build when a stop or page has no entry. Operator hours and tenant reference hours remain distinct. Weather triggers share the photo metadata glass material; their native popover uses a dimmed backdrop.

The initial page is prerendered so the first day and PDF link remain available without JavaScript. Selecting a day requires JavaScript. Each date uses a `#YYYY-MM-DD` fragment; Back/Forward restores the corresponding date.

The calm option has the same two planning views. `/places/calm-itinerary/` (`src/calm-itinerary.ts`) reuses the homepage's day components from `src/render.ts`; all 14 days are prerendered and stack in order without JavaScript; with it, a one-line inline script sets `.js` before the panels are parsed so `src/calm.css` shows only the linked day (`:target`) from the first paint, and `src/calm-itinerary-main.ts` then shows one day at a time with the same `#YYYY-MM-DD` history, sidebar, mobile day bar and picker. `/places/calm-prepare/` (`src/calm-prepare.ts`) mirrors `/places/prepare/` with the main plan's bookings for 8 and 18–21 November plus the calm bookings, grouped by urgency, and a section of what not to buy. Dialogs, copy buttons and the photo viewer for both day views live in `src/day-controls.ts`.

`npm run build` exports a script-free print document and generates the downloadable PDF with Playwright Chromium. Download links receive a fresh cache key per build and browser session so a CDN cannot retain an earlier itinerary at the same URL. The development server generates the PDF on request from freshly loaded source data; concurrent downloads share the in-progress generation. Both paths use local resources only and include a generation timestamp and author credit.

## Current temperature

Sightseeing photos in the daily itinerary and every destination guide show compact badges for current temperature and apparent temperature from [Open-Meteo](https://open-meteo.com/en/docs). These are model estimates for the named reference area, not local station observations or forecasts for the November itinerary dates. The provider's timestamp is displayed in China time (UTC+8). Each badge uses the pictured destination’s reference area. Tapping it opens a native popover with the provider timestamp, source, reference location, refresh control, and mountain-area limitations. Only temperature and feels-like values are visible by default.

`src/weather-locations.ts` owns the verified coordinates and the mappings for 31 guide groups. Coordinate sources and verification notes are recorded in `source/weather-locations.json`. `src/weather.ts` renders the shared photo badge and its details popover and loads the public API directly in the browser without an API key or user geolocation. Readings are cached in memory for 15 minutes, simultaneous requests for one location are shared, and the refresh button requests new data. Loading skeletons, a 10-second timeout, retry controls, and a visible warning for data older than 45 minutes handle unavailable or stale responses. Invalid values are never replaced with zero. Without JavaScript, the reference location, attribution, and a loading explanation remain available through the native badge popover.

This personal, noncommercial site uses the [Open-Meteo free API terms](https://open-meteo.com/en/terms), with attribution in every weather popover. API availability is not guaranteed. Reassess the service terms before commercial use. Weather tests mock provider responses so CI does not depend on the live API.

## Rupiah estimates

Chinese-yuan prices retain their original amount and display an approximate rupiah equivalent, including ticket components, alternatives, explanatory text, historical-price cautions, and daily practical notes. Existing IDR prices and free or unconfirmed prices are preserved. The shared formatter in `src/currency.ts` escapes plain text before adding conversion markup; it never rewrites completed HTML or link attributes.

The initial static documents use a verified, dated ECB reference-rate snapshot recorded in `source/currency-rate.json`. The browser checks the [ECB-specific Frankfurter feed](https://api.frankfurter.dev/v2/providers/ecb/rate/CNY/IDR) once per page and updates every conversion when a valid newer rate is available, including content shown after switching dates. If the request fails, times out, or returns invalid data, the dated reference remains visible with an explanation. Prices remain available without JavaScript. The source and rate date appear beside the relevant costs; estimates are rounded to whole rupiah and payment-provider rates or fees may differ. These are daily reference rates, not live trading quotes.

The generated application module uses `data-cfasync="false"` to exclude it from Cloudflare Rocket Loader. Image-loading skeletons and navigation must initialize while photographs are still downloading, rather than waiting for the window load event. See [Cloudflare's script exclusion documentation](https://developers.cloudflare.com/speed/optimization/content/rocket-loader/ignore-javascripts/).

Sharing metadata is rendered into the HTML for crawlers that do not run JavaScript. Open Graph and large-image cards use the Jiuzhaigou autumn photograph at `/social/jiuzhaigou.jpg` (1200 × 630 JPEG); destination documents keep their own titles, descriptions, and canonical URLs. Photo provenance is recorded in `source/social-image.json`.

## Testing

```sh
npm run test:e2e
```

Playwright uses local Google Chrome and installed Chromium in GitHub Actions. This command builds the site and starts a production preview if no server is already running on port 4173. Tests cover 360, 390, and 1440 px layouts, all dates and overnight stays, reaching 20 November in two taps, reload/Back navigation, dialog focus, clipboard copying and its fallback, aXe accessibility checks, WebP assets, and a throttled mobile network.

Test evidence is stored in `artifacts/`: screenshots, JSON test results, aXe results, and network records. Sources and evidence limitations are documented in `SOURCE-NOTES.md`. The design review is in `artifacts/finish-review.md`.

The local `artifacts/` directory is excluded from Git. GitHub Actions uploads test results as workflow artifacts. The visual system is documented in [DESIGN.md](DESIGN.md), with components and tokens in `.impeccable/design.json`.

## Destination guides

`src/guides/*.ts` contains researched regional data typed by `src/guide-types.ts`: 31 research groups cover 48 sightseeing stops across 56 destination routes, including the revised first-day Chengdu city walk. Two credited Chengdu photographs accompany the new guide. Each sightseeing stop maps to a page; airports, stations, transfer-only stops, and hotel bases are excluded. Related stops share park or town transport and ticket data, with stop-specific final-leg directions. Shared tickets are explicitly identified on individual stop pages so their price is not counted twice.

`src/guides.ts` owns the route registry, itinerary-date lookup, and gallery selection. `src/guide-render.ts` renders the guide and directory; `src/guide-main.ts` enhances galleries with native dialogs, keyboard navigation, and focus restoration. `vite.config.ts` emits real static HTML for `/places/` and every `/places/<slug>/` route. Direct navigation and reload work without a client-side router. The guide content, sources, photos, and links remain available without JavaScript.

Route references and the complete source list are visible without opening accordions. Each guide shows its research check date near the top; known source publication dates are displayed separately. Cost rows link directly to their supporting reference, while itinerary time allocations and editorial tips are distinguished from published operating rules.

New research should include source URLs, the applicable season, and the actual check date. Record `publishedAt` only when the original publication date is verified; never substitute a crawl date or research date. Never promote an old quote or a temporary offer to a confirmed future price. Yading's 2026 pricing changes and weather-dependent upper-lake access require a final operator check. Private-car quotes remain unconfirmed where no reliable fare is available.

The browser suite covers all generated documents, complete sightseeing-stop coverage, source-linked costs, direct reloads, no-JavaScript content, gallery keyboard handling, mobile layout, a consistently light theme under either device color preference, and reduced transparency. The deployment tests also exercise nested destination pages and reject traversal or arbitrary files.

## GitHub Actions and Nginx

The [Test and deploy](.github/workflows/deploy.yml) workflow runs on pull requests and pushes to `main`. CI installs Node 24, runs the build and browser tests, and packages a verified static archive. Only pushes to `main` or manual runs on `main` can deploy to the `production` environment.

Nginx serves `current/public` on the server. The dedicated deployment key is restricted to the `ops/deploy.py` handler and cannot run arbitrary shell commands. The handler validates the archive and hashes, activates the release atomically, checks origin HTTPS, and restores the previous release if verification fails. The workflow also checks the commit marker over public HTTPS.

Nginx configuration: [ops/nginx.conf](ops/nginx.conf). Installation, environment secrets, and rollback: [ops/README.md](ops/README.md). Raw photos, build archives, local evidence, and credentials are excluded from Git; all WebP assets required for the build are in `public/`.
